### 3. モック認証システムの問題分析

#### 3.1 既存実装の調査とモック認証追加の詳細経緯

**前任者の実装状況**:

- システムは本来AWS Amplify/Cognito認証を前提として設計
- `amplify_outputs.json`には実際のAWS設定が記載されていたと推定
- 本番運用を想定した認証フローで開発

**引き継ぎ時の発見事項**:

- **ログイン画面**: `app/routes/auth/login.tsx`（Amplify Authenticatorコンポーネント使用）
- **モック画面**: `app/routes/auth/login-mock.tsx`（後から追加されたと推定）
- **環境変数**: `.env.development` で `VITE_USE_MOCK_AUTH=true` 設定済み
- **モック実装**: `app/lib/amplify-mock.ts` でクライアントサイド認証のみ実装済み

**モック認証追加の経緯推定**:

1. 前任者または引き継ぎ準備段階で、AWS環境の課題を認識
2. 開発継続のための暫定措置としてモック認証を部分実装
3. しかし、サーバーサイドレンダリング対応が不完全で動作不良
4. 今回の作業で完全なモック認証システムを実装

#### 3.2 問題の特定

**症状**: モックログインボタンを押しても反応しない

**原因分析**:

1. **サーバーサイドレンダリング（SSR）の問題**

   - `protected/layout.tsx`のloaderはサーバーサイドで実行
   - モック認証はクライアントサイドのlocalStorageを使用
   - サーバーサイドではlocalStorageにアクセス不可

2. **認証フローの不整合**
   - モック認証: クライアントサイドのlocalStorage
   - 実際の認証チェック: サーバーサイドのAmplify認証
   - 両者の連携不備により無限リダイレクトループ

### 4. モック認証システムの修正実装

#### 4.1 サーバーサイド認証チェックの修正

**ファイル**: `app/routes/protected/layout.tsx`

**修正内容**:

```typescript
export async function loader({ request }: Route.LoaderArgs) {
  // モック認証モードの場合
  if (import.meta.env.VITE_USE_MOCK_AUTH === "true") {
    // Cookieからモック認証トークンを確認
    const cookie = request.headers.get("Cookie");
    const mockAuthToken = cookie?.includes("mockAuthToken=mock-token");

    if (!mockAuthToken) {
      return redirect("/login");
    }

    // モックユーザー情報を返す
    const mockAccount = {
      id: "mock-account-123",
      email: "dev@example.com",
      name: "開発ユーザー",
      employeeId: "DEV001",
      department: "開発部",
      location: "東京",
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
    };

    return data({
      account: mockAccount,
      error: null,
    });
  }

  // 本番モード（既存のAmplify認証処理）
  // ...
}
```

## 技術的解決策の詳細

### サーバーサイドレンダリング対応

**課題**: React Router v7のSSRでlocalStorageが使用できない  
**解決策**: Cookieを使用してサーバーサイドでも認証状態を確認

### 認証状態の一貫性確保

**課題**: クライアントとサーバーで異なる認証メカニズム  
**解決策**: 環境変数による分岐とCookie + localStorageの併用

### 本番環境との互換性

**課題**: モック認証と本番認証の共存  
**解決策**: 環境変数による完全な分岐実装
